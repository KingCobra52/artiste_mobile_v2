# History charts

Artist charts reconstruct the existing virtual pricing formula at each observed date using only snapshots up through that date. The API paginates the aggregate snapshot RPC to avoid silently losing dates at the database row limit. Dates use UTC. No observations are inserted into collection gaps; SVG lines break when adjacent observations are more than one day apart. Older source signals are identified in the point readout. These are reconstructed prices, not an immutable record of previously executed quotes: same-day ingestion can revise snapshots.

The read-only database inspection found 70 Last.fm dates (July 27–October 22, 2026), 83 YouTube dates (June 30–October 22, 2026), and zero paper trades. There is no stored portfolio valuation series. The portfolio chart therefore shows a single current valuation, with cash and holdings separated in the readout, and explicitly says no historical valuations have been recorded. It does not create a flat $10,000 past or use today's positions to value earlier dates.

Record the pricing version and quote timestamps used. Read this series from the existing /portfolio/history endpoint. Do not backfill dates before collection starts unless an opening balance and complete cash/position ledger can be established. No migration or production scheduling changes were made in this task.

Both history endpoints require the verified user token. Portfolio identity comes only from that token. Next.js fetches through the server-only API helper. History failures are isolated from the rest of the page. The chart uses proportional date spacing, pointer inspection, a native keyboard slider with date/value announcements, textual status, and a one-point/empty-state explanation.

Tests cover gap preservation, the price cap, no future data, invalid/missing signals, artist isolation, and stale source dates. Browser coverage exercises slider Home/ArrowRight, pointer hover, and the portfolio coverage disclosure.
